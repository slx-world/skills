# AI 表格数据源插件生成器

根据用户的数据源和运行环境，交付可运行、可验证的钉钉 AI 表格数据源插件工程。使用用户的语言沟通。这个技能是根据开发指南制作的 Codex 版本，不宣称是千问办公官方技能。

## 开始工作

1. 阅读 [协议说明](references/protocol.md)，实现前后端协议时以它为基线；需要新增字段类型、账号托管或发布时，按参考文件中的链接读取当前官方说明。
2. 从对话和现有工程确定数据源（数据库或 API）、要同步的实体、字段、稳定唯一键、部署环境和认证方式。已有信息不重复询问。缺少真实连接信息时先完成示例和可替换的适配器，明确尚未接通的部分，不索要聊天明文密码。
3. 读 [适配器实现指南](references/adapters.md)，按目标源实现查询、类型映射和分页。已有工程遵循原有技术栈，做必要修改；新工程可使用附带的 Node.js 原生 HTTP 服务 + 原生前端模板，也可按用户指定技术栈生成等效实现。

## 生成工程

运行下列脚本创建一个**不存在的**输出目录（路径相对当前工作目录，脚本路径相对本技能）：

```text
python scripts/scaffold.py --output <工程目录> --name <项目名>
```

模板包含示例数据适配器、两条 POST 回调、原始 Body 验签、前端 initView/saveConfigAndGoNext、协议测试、环境变量示例和启动说明。它是可运行的起点，不能把示例数据当成用户的真实数据源。

生成后完成这些与需求有关的实现：

- 替换 `server/adapter.mjs`；为真实数据库/API安装所需驱动，复用服务端连接配置。只允许前端保存非敏感选择或服务器端连接标识。凭据留在服务端环境变量、密钥存储或已配置的账号托管流程中。
- 修改配置页，供用户选择连接、表、字段、过滤条件等。初始化成功后才启用下一步，保存失败保留输入并显示错误。`params` 的结构在前后端保持一致。
- 固定字段 ID 和记录 ID，恰好一列 `isPrimary: true`，记录的 `fields` 用字段 ID 作键。主键和显示名称是不同概念，勿根据字段显示名称生成易变 ID。
- 保留未知 `context` 字段的兼容性，在验签通过后解析原始请求体。不得用 JSON 重序列化结果计算签名。
- 实现确定性分页和完整的结束状态。对超时、限流、空结果、上游鉴权错误给出协议错误码，避免内部异常或凭据进入返回值和日志。
- 缺少签名密钥时模板拒绝启动；演示测试通过注入密钥运行，不添加默认密钥或验签绕过。时间戳有效期并非指南规定值，只有确定平台时间戳单位和容差后才增加可配置的防重放策略。

模板的 `npm test` 和 `npm start` 仅运行服务端，不安装外部依赖。前端需在 `frontend/` 执行 `npm install`、`npm run build`。生成真实项目时核对 SDK/构建依赖版本，保存 lockfile，避免随意执行上游仓库的安装脚本。

## 验证与交付

运行 `npm test`，为实际适配器补充覆盖业务不变量的测试：跨页无漏重、稳定 ID、类型转换、租户边界和上游错误。再构建前端并检查窄容器显示。SDK bridge 只在钉钉宿主内验证；普通浏览器只能检查页面和错误提示，不能据此声称钉钉联调通过。

对数据库/API只在用户已授权的目标和范围内做连接测试。没有账号时用固定样例或本地 mock 检查契约，不伪造真实连接成功。以 10 秒（元数据）和 20 秒（记录）平台超时为外部预算，查询/重试须留出返回余量。

交付工程、启动命令、配置项名称、字段映射和已完成检查。清楚区分本地协议测试、前端构建、真实数据源连接、钉钉端联调和上线发布各自的完成状态。

需要发布/联调时阅读 [发布说明](references/release.md)。创建技能或生成代码不自动授权部署、开启公网隧道、修改应用可见范围或发布真实企业应用；根据当前用户请求和实际授权执行。
