# 联调与发布

来源为开发指南中 3.2 企业内插件、3.3 三方企业插件与第4部分开发指引。平台界面和发布要求会变化，实际操作前重新读取相应官方页面；不把文档中的个人联系人、内部审批链接或历史截图固化为自动操作。

## 本地验证

生成工程后配置环境变量，执行 npm test，启动服务并用经过签名的 POST 请求验证两个回调。构建前端，检查默认 300×450 的布局和 SDK 初始化/错误反馈。普通 localhost 页面没有钉钉 bridge；只能证明本地页面可用。

## 企业内插件

在[钉钉开发者平台](https://open-dev.dingtalk.com/)创建企业内部应用；添加酷应用，选择扩展到 AI 表格、数据同步插件，填写前端 URL、后端服务 URL、两个回调路径和双方约定的签名密钥。插件前端使用 HTTPS；后端必须能够被平台服务器访问。

在应用发布/版本管理与发布中创建版本，限定测试可见范围。到 AI 表格的添加/导入、从其他数据源同步、数据连接中心的企业专用中找到插件，完成配置、表结构与多页记录同步检查。平台统一配置页负责字段选择、定时同步等；插件无需再实现一套调度页面。

验证成功后按用户授权范围调整可见性并发布。生成代码不等于已发布。无平台账号或权限时交付部署/注册步骤和待填 URL，不声称已联调或已上架。

## 第三方插件

先按当前[酷应用说明](https://open.dingtalk.com/document/orgapp/cool-application-overview)、服务商入驻和三方应用发布要求确认企业资质、授权/商品等流程。账号托管、免登和第三方授权均按当前官方文档实现。只在需求确实涉及该能力时加载详细文档，不用企业内插件流程替代第三方发布。

公网隧道会暴露本地服务。只在用户授权联调和外部暴露范围后开启；提供准备好的本地工程和明确端口、域名、时长作为可审阅对象。生产使用用户选择的正式部署方案。
