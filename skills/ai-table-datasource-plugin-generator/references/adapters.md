# 数据适配器实现

模板 `server/adapter.mjs` 接口：`getMeta(params, context)` 和 `getRecords(params, {maxResults,nextToken,context})`，返回的是 envelope 内的 data。错误用带 `code` 的 Error，主路由负责包装和隐藏未知异常。示例只支持 connectionId=demo。

## 输入与身份

从上下文和服务器连接配置中解析真实连接，前端参数只保存连接标识、表、列或用户需要的业务条件。不要把数据库密码、应用 secret 或长期 token 放进配置页静态包、URL、saveConfigAndGoNext 或日志。凭据托管仅在确实配置该能力时使用 context.credentials；不要假设它总有值。

客户端传来的表名、列名不能直接拼接 SQL。用服务端允许的 schema 元数据验证标识符，再使用目标驱动的转义/引用方法；WHERE 值必须参数化。数据库账号只需读取目标表的权限。查询和调用应有超时，失败时释放连接。

## 适配数据库

- MySQL：按用户环境选择可用驱动（常见 mysql2），检查数据库/schema、表、列、唯一键，复用连接池。
- PostgreSQL：使用合适驱动（常见 pg），区分 schema 和表名，参数化值，注意 bigint/numeric 精度。
- SQL Server：使用合适驱动（常见 mssql），确认 TLS 和账号方式，用确定的 ORDER BY + keyset 或 OFFSET/FETCH 实现分页。

这些是实现方向，不代表模板已经包含驱动。根据实际任务查询当前驱动官方文档，安装依赖并验证；不要仅为声称多库支持而添加未使用的驱动。

有稳定唯一键时优先 keyset 分页，固定排序并将最后唯一键编码进 token；复合键必须编码所有组成部分且无碰撞。源会变化且要求一致快照时，使用可持续分页的快照或源支持的版本边界。offset 仅适用于明确稳定的数据集/快照，并说明变化时漏重风险。record.id 不能用当前页行号、数组下标或随机 UUID。

元数据列 ID 映射到稳定的源列标识，显示名称变化不能导致 ID 变化。源没有唯一键时确定真实业务复合键；不能保证唯一性就明确限制，不能静默伪造。`isPrimary` 仅一列；复合业务键可用派生文本列表示。

## 适配 HTTP API / ERP

读取用户提供的官方 API 文档，确认认证、签名、时间戳、分页、字段类型、速率限制；API 自己的签名与钉钉回调签名分别实现。模板不预设某家 ERP 的 token/分页或 endpoint。

将 API cursor 或页号封装为平台 token；绑定连接、筛选条件和授权范围，避免跨租户复用。每次上游请求设超时，重试限于幂等读取且总耗时低于平台预算。上游一页大于 maxResults 时保留未返回部分或生成能正确续读的状态，不能直接丢弃。token 敏感时存服务器端或用带完整性保护的 opaque token，不塞明文密码。

## 类型与行预算

优先无损映射：普通字符串 -> text；确实可安全表示的数值 -> number。long/bigint、精确货币、大 decimal 可能超出 JS number 精度，按用户需求保留文本或明确转换规则。空值不要擅自变成空字符串/0。日期时区、布尔、人员、附件、选项等先查当前官方对象模型，再实现相应字段和记录值结构。不能用任意 JavaScript 对象冒充平台单元格。

context.fields 存在时按已验证结构投影，仍需包含标识记录必需的源键。context.maxImportRowCount 限制全任务累计量，分页 token 或服务器状态应携带已处理数量。若仅截断而非全量同步，向用户说明截断规则。

## 验证

至少用多于一页的固定数据核对所有 ID 只出现一次；空源和恰好一页都正常结束；重复主键不静默覆盖；ID/列 ID 跨请求稳定。验证非法 token、无权连接、无权表、上游401/403/429/5xx和超时。多企业时增加 A 企业不能访问 B 连接的测试。测试不要连接未授权生产系统。
